# Компактная проработка задач разработки Second Brain

Это вспомогательное руководство для **разработки исходного кода**, а не новый агент обработки пользовательских заметок. Оно дополняет `AGENTS.md`, действующие роли и Night Shift, но не заменяет их.

## Выбор достаточной глубины

| Изменение | Как работать |
| --- | --- |
| Простая локальная и обратимая правка | Выполнить непосредственно; существующих требований и прицельной проверки достаточно. |
| Новая функция или несколько связанных модулей | В Issue/PR указать критерии, владельца данных, интерфейс, обратную совместимость, тесты и откат по применимости. |
| Реальная запись в vault, доступ к приватным данным, небезопасный внешний вход, необратимая операция, новая интеграция | До реализации проверить решающий риск и обязательные ограничения `AGENTS.md`; неподтверждённые зависимости оставить открытыми. |

Глубина регулирует **объём размышлений и проверок**, а не число обязательных агентов, файлов, делегаций или запусков.

## Контракт и доказательства

Для нетривиальной задачи использовать существующие Issue/PR, не создавать отдельную БД или локальное состояние рабочего процесса:

- Записать начальное и ожидаемое наблюдаемое поведение и источник истины: Markdown/YAML vault, конфигурация, тестовая фикстура или код.
- Связать каждый критерий с конкретным сценарием и фактическим доказательством: команда, статус, окружение, SHA и изменённые пути.
- Разделить `UNIT/MOCK`, `INTEGRATION`, `LIVE`, `PRODUCTION`. Синтетический vault не подтверждает реальный private vault.
- Для Safe Write сохранить прежнюю последовательность `preview/diff -> prepare -> explicit apply`; при записи проверить согласованность и чтение обратно, обработать повтор/конфликт/rollback по существующему контракту.
- Не раскрывать содержимое `second-brain-vault`, личные заметки, настоящие токены и чувствительные материалы в PR, отчётах или внешних моделях.
- Для UI соблюдать текущий контракт русского текста, адаптивности и отдельные визуальные согласования.

## Рецензирование и экономия действий

Рецензирование остаётся **существующим bounded Codex Code Review** по правилам Night Shift: после точного SHA и зелёных обязательных Checks, с установленным максимумом повторов. Не запускать дополнительного независимого reviewer subagent, критика или судью поверх действующего контракта. Для обычной работы достаточно основного профиля и одной дополнительной роли, только если она действительно нужна.

До правки кода проверять исходный дефект, если он воспроизводим; после - целевые тесты и один финальный набор применимых обязательных проверок. Не перечитывать неизменённые материалы и не повторять уже успешные проверки без нового основания. Для изменений документации не создавать фиктивный цикл «сначала падающий тест».

## Передача результата

В PR отразить:

1. Что изменено и какие критерии проверены.
2. Команды и фактический результат, контур, ссылки на exact-head CI.
3. Какие критерии не проверены, где нужен человек или внешний доступ.
4. Какие согласования остаются до merge/deploy.

Никаких новых контроллеров, очередей, локальных баз задач, обязательной телеметрии токенов, автономного commit/push/merge/deploy. `Night Shift` и `second-brain-vault` сохраняют свои независимые ограничения; руководство не выдаёт разрешений на сеть, модель, данные или запись.
