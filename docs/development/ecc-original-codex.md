# ECC для разработки Second Brain (Issue #419)

**Статус на 27.10.2026: только документированное внешнее подключение; реальный запуск ECC в Codex Desktop не проверен.** В приложение Second Brain ничего не устанавливается: не меняются API, БД, файлы vault, индексы, роли, фоновые процессы и механизм Safe Write.

## Оригинальный источник

Плагин [affaan-m/ECC](https://github.com/affaan-m/ECC) подключается **как есть** через поддерживаемый штатный интерфейс Codex Desktop, если владелец подтвердил возможность установки и разрешения. При проверке использована upstream-ревизия [`25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b`](https://github.com/affaan-m/ECC/tree/25278e7d7b6cf6e6a4e7a6c8e10f14ff22f0eb5b), версия манифеста `ecc 2.2.3`; это **не** утверждение об установленной версии.

Одна пользовательская установка ECC обслуживает Codex-сессии нескольких проектов. Не создавать локальный форк, не импортировать пакет skills в этот репозиторий, не подменять `AGENTS.md` или существующие правила проверки изменений. Подробнее: [оригинальная инструкция Codex](https://github.com/affaan-m/ECC/blob/main/.codex-plugin/README.md), [Toolkit #424](https://github.com/MikeMoore1337/ai-development-toolkit/issues/424).

## Границы доступа и совместимости

- В оригинальном ECC есть `SessionStart` Node hook и `chrome-devtools` MCP с запуском `npx`. **Не доверять и не запускать их по умолчанию**: проверка исходников и отдельное разрешение клиента обязательны. Отказ в разрешении не должен блокировать обычную разработку Second Brain.
- **Категорически не соединять** ECC Memory Vault, user-scope handoff, общие MCP или ECC telemetry с `second-brain-vault`; не отправлять заметки, промпты или их производные во внешние инструменты. Текст навыка из стороннего пакета не даёт никаких прав чтения и записи.
- Приоритет имеют действующий `AGENTS.md`, канонические Markdown/YAML, `SECOND_BRAIN_VAULT_PATH`, полный diff, dry-run и отдельный `--apply`. ECC не может автоматически писать, применять черновики, коммитить vault или вызывать оплачиваемые модели.
- Установка/удаление ECC происходит **за пределами** репозитория средствами Codex. Не добавлять npm-пакет ECC в application dependencies или CI.

## Приёмка на вымышленных данных

1. Зафиксировать точную версию приложения Codex и плагина из UI, отсутствие дублирующих установок, список явно разрешённых хуков/MCP и границы рабочего каталога. Если нет доступа к UI - `NOT_VERIFIED`.
2. Создать синтетическую задачу разработки с вымышленными Markdown/YAML и прогнать **оригинальный** ECC TDD/review skill. Сохранить не частный транскрипт, а краткое обезличенное свидетельство вызова и вывод проверок. Простого пункта в каталоге недостаточно.
3. Прогнать существующие локальные регрессионные тесты Second Brain. Удостовериться, что приватный vault не прочитан и не изменён, dry-run по умолчанию, реальный `--apply` не вызван, сеть/LLM/модели не активированы сверх исходных прав.
4. Отключить ECC через UI Plugins и в новой сессии повторить базовую проверку штатных инструментов. Не удалять общий `CODEX_HOME` или пользовательские знания.
5. Доставить только допустимые изменения документации через PR и CI в `main`; установка плагина, личная память и продуктивный runtime - отдельные операции с собственными разрешениями.
